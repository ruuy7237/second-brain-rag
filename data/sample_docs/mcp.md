# MCP：把工具接进模型客户端

## 它解决什么问题
在 MCP 出现之前，每接一个新数据源都要写一套私有适配代码，接十个工具就有十份胶水代码，换个客户端还得重来一遍。MCP 定义了一套统一的协议，把资源、工具和提示模板以标准格式暴露出来，任何实现了协议的服务端都能被支持协议的客户端直接挂载。

## 三个基本角色
宿主是真正跑模型的客户端，比如编程助手或桌面应用；服务端是被挂载的能力提供方，例如本地文件系统服务、Git 仓库服务、数据库查询服务；两者之间用 JSON-RPC 风格的消息通信，传输可以是标准输入输出也可以是 HTTP。服务端只需要声明自己有哪些工具、每个工具接受什么参数，客户端负责把这些信息翻译成模型能理解的函数定义。

## 什么时候值得做
如果你写的能力只给自己一个应用用，直接写成函数更简单。但当你希望同一份能力被多个客户端复用时，把它包成 MCP 服务端就划算了，尤其是本地知识库、命令行工具封装这类场景。
