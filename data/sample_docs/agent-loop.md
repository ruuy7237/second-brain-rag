# Agent Loop：让模型真正干活

## 一次循环里发生了什么
一个工具调用型智能体的核心是一个循环。系统把用户任务和可用工具的说明书一起交给模型，模型判断是该直接回答还是要调用工具；如果要调用，就输出工具名和参数，程序在本地执行工具，把执行结果作为观测回填进上下文，再让模型继续判断。这个过程重复到模型认为信息足够、输出最终答案为止。所谓 ReAct 就是把这个思考、行动、观测的循环显式写出来。

## 必须有的四道防护
第一是参数校验：模型常常填错字段名或类型，不能直接抛异常，而要把错误原因回喂让它重发。第二是结果校验：工具报错或返回空值时，带着提示重试一次，避免把错误信息当事实写进上下文。第三是步数护栏：设置最大步数，超出就终止并记录失败原因，否则会出现死循环把 token 烧光。第四是幂等与沙箱：文件读写限制在指定目录，数据库只允许只读语句。

## 为什么手写
框架能让人十分钟搭出原型，但手写一遍会逼你回答很多问题：上下文里保留多少历史观测、多个工具调用的先后顺序如何、失败怎么重试、要不要让模型先输出计划。这些决策恰恰是影响任务成功率的变量，也只有手写过，调优时才清楚该动哪里。
