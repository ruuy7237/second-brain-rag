# 微调：什么时候才该动它

## 先确认问题不在别处
九成的效果问题不需要微调。先检查三件事：提示词是否写清楚、有没有给足够示例、能不能通过检索把正确材料送进上下文。这三条成本极低，改动即时生效，微调相比之下又慢又贵。

## 微调真正擅长的两件事
一是稳定输出特定格式或风格，例如始终按固定模板出具摘要、始终使用某种术语体系；二是压缩提示词长度，把大量少样本示例蒸馏进参数里，从而省下每次请求的 token 开销。它不擅长注入新知识，新知识交给 RAG。

## 工程上的坑
数据质量远比数据量大重要，几百条干净样本常常胜过几万条噪声样本。要严格划分验证集，否则学到的只是记忆。参数高效微调例如 LoRA 成本低、易回滚，是入门首选。上线前必须与基线做同评测集对比，否则无法证明这一轮训练是赚了还是赔了。
